# ThreadLine UI / UX 评估基线

日期：2026-10-26（Asia/Shanghai）。结论：**需要优化，并做有限的前端交互重构；当前没有证据支持整体重写。**

## 评估对象与证据边界

本次冻结 [main 3ce5d930](https://github.com/siskosun/ThreadLine/commit/3ce5d93040fa44cd3a5dda109da2c87b5343fc0d)，应用源码 v0.8.2。通过 GitHub 连接器核对提交后拉取并建立独立文档分支，未修改生产 JS/CSS、数据协议或用户安装。

PR #37 的 `78d3795` 仍为独立 Draft，其 S2–S5 功能不能当成当前 main。此前候选审计中“默认网页自动分析”“变化提醒隐藏”等发现重新核对后分别判为已修复、不适用于 main，未沿用为本轮缺陷。

证据来自当前源码、只读信息结构复审，以及临时 Chromium/MV3 配置中的真实扩展页面。后者使用完全合成数据，未打开真实 ChatGPT、未调用模型服务、未发送消息。浏览器 Chromium 156.0.8078.4，Playwright 1.62.1，Windows，DPR=1；主要视口 360×900，另测 320/768/1280px。

采集了 17 个状态截图及 DOM 测量，原始记录见 [测量 JSON](baseline/measurements.json)。这是一组确定范围的界面探针；不是全部功能 E2E、真人可用性试验、完整 WCAG 审计或渲染性能基准。读屏、真实侧栏缩放、真实登录页面与真实用户完成率仍未执行。截图中长页在文档查看器里可能缩小，请按原尺寸阅读。

## 产品方向与整体判断

现有视觉方向可保留：蓝灰色、白色内容区、轻边框，适合持续阅读；三主导航已有明确分工，默认手动分析、逐条采纳、来源限制提示、可编辑交接也符合研究任务。当前问题主要发生在“找到入口、判断范围、找到记录、读懂反馈”这些环节。

| 维度 | 评价 | 主要依据 |
| --- | --- | --- |
| 产品与任务分工 | 基础成立 | 三工作区；Fork 独立页面；高级能力可折叠 |
| 状态与证据表达 | 保留并完善 | 仅片段、已保存/摘要待更新已区分；历史保存但阅读入口不足 |
| 可读性 | 需要优先修复 | 非激活导航对比度不足，必要说明字号偏小 |
| 内容规模 | 需要局部结构调整 | 200 条结论逐条全文展开，交接/维护入口落在长列表之后 |
| 操作范围 | 需要优先明确 | 两种备份概念相近、维护另有独立课题选择器 |
| 交互一致性 | 需要统一 | prompt/alert/短 toast/完整表单并存 |
| 底层架构 | 暂无重写依据 | 原生组件与既有状态保护可复用；观察到的是前端任务结构问题 |

### 内容规模

固定正文为一条约 50 字的合成判断、适用条件及一个手工证据片段；每条仍有修订和撤回按钮。下表是页面高度，不是加载耗时。

| 结论数 | 360px 页面高度 | 以 900px 视口折算 |
| --- | ---: | ---: |
| 1 | 944px | 约 1.0 屏 |
| 10 | 3,150px | 约 3.5 屏 |
| 50 | 12,956px | 约 14.4 屏 |
| 200 | 49,730px | 约 55.3 屏 |

200 条在 320px 时为 57,547px，768/1280px 时为 45,021px。该夹具中 document 宽度均等于视口宽度，未观察到整页横向滚动；这不能证明所有元素都不被裁切，也不能代替 200% 放大验收。没有凭这些数据宣称“已卡顿”。

管理展开页高 1,500px；合成采集结果页 2,205px；Fork 启用后新建页 1,538px，冻结一个实验后 2,301px。截图与测量支持减少重复说明和分层展示，但页面越短不必然越好。

以下 P1/P2 表示本次体验改进顺序，不是对已发生数据事故的等级判断。

| ID | 优先级 / 发现 | 用户影响与建议 | 源码依据（冻结 SHA） |
| --- | --- | --- | --- |
| UX-01 | P1：文字偏小、次级颜色过淡 | 非激活导航仍是高频入口。统一语义色和字号，先修导航、空状态、必要说明，再迁移其他组件。 | `panel.css:13–21,69,104,107`；`ui-polish.css:2–12`；测量 JSON |
| UX-02 | P1：两类备份范围说明不足 | “课题备份”写包含结论历史，实际是旧 state；证据完整包另有入口。主按钮的“覆盖当前课题”又小于实际替换范围。统一导航、明确包范围和作用对象；先保留原有格式及事务。 | `panel.html:64–69`；`panel.js:290–297`；`background.js:1338–1342`；`backup-core.js:18–23`；`evidence-maintenance-ui.js:43–53` |
| UX-03 | P2：部分空状态只有路径说明 | 无活动对话或证据课题时，用户需要记住另一工作区的路径。给“创建课题”“整理当前对话”的对应按钮并回到原任务。有未关联的 ChatGPT 对话时已经存在直接创建入口，不能说所有创建都隐藏。 | `panel.js:133–175,460,477` |
| UX-04 | P2：长列表缺少查找机制 | 先做本地搜索、采纳/撤回筛选、摘要与详情；交接动作独立于列表尾部。优先任务查找，再根据真实性能决定是否虚拟化。 | `panel.js:477–488`；`panel.html:158–165`；200 条夹具 |
| UX-05 | P2：保留历史但缺少完整阅读入口 | 证据 UI 只展示 current 正文及版本计数；旧课题历史仅最近 8 条、前后文各截 180 字。增加按需版本列表与完整差异，不改历史语义。 | `panel.js:228,240,477,481–488` |
| UX-06 | P2：查看与维护课题不同步 | 主视图 A 与维护选择 B 可以并存，虽已有危险范围预览，仍增加判断负担。默认维护当前课题，跨课题切换显式化；每次确认继续列真实目标。 | `panel.html:153–154`；`evidence-maintenance-ui.js:44,57–64` |
| UX-07 | P2：Fork 以内部信息作为主标识 | 列表难以凭任务辨认，首层 W₀/P/K、revision、SHA 增加阅读成本。由已有指令派生标题，展示日期和进度，把校验信息放入详情；无需为显示名立即改 schema。 | `ff.html:28,41–42,60–68`；`ff-page.js:286–289,325–327` |
| UX-08 | P2：错误和编辑机制不一致 | 分支编辑仍用 prompt，撤回失败 alert，面板错误 toast 约 3.1 秒；重要错误应就地保留并给恢复动作。复用现有 dialog，避免新增框架。 | `panel.js:61–67,400–405,537,550–556`；`ff-page.js:45–49` |

备份和跨课题发现是已确认的 UI 范围表达问题，未据此推断已经误删或丢失数据。找内容、认实验等用户后果属于设计判断，须用 [验收清单](CHECKLIST.md) 的真人任务验证。

研究整理页还呈现出多种任务同时竞争：阅读提要、AI 分析、导图、网页项目/归档、接续。建议把阅读/采纳放在主路径，将网页整理放入次级操作组；保留当前默认手动模型分析。该项是截图支持的层级优化建议，不认定所有用户都需要更短页面。

## 重构决定与顺序

1. **先做可读性和范围修复。** 统一 token、必要字号、备份范围名与实际目标。验收：文字颜色通过指定组合检查，用户能准确说出导出和替换范围。
2. **再做有限交互重构。** 抽取课题上下文、列表/详情、版本入口、反馈与表单；新增搜索/筛选和空状态动作。验收：50/200 条查找任务可完成，完整正文/历史可读，原状态防护回归通过。
3. **最后评估后续研究工作台。** S2–S5 单独进入集成范围时，才对待核对提醒、局部关系与复核任务做主层级设计；不把未集成能力作为当前 main 的 UI 依赖。

复用当前 `ui-dialogs.js`、采纳窗口、三导航与原生 HTML。逐步收敛 `panel.css`、`ui-polish.css`、Fork 内联样式的重复规则。只有当局部改造已实测无法解决明确问题时，才另开框架替换或大规模重写决策。
