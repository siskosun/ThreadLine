# ThreadLine UI-D0 / UI-D1 双层界面交互契约（2026-10-27）

**基线**：GitHub main `52f44779a00890e3e06f762d989f93765a872bec`；manifest v0.8.2；旧版 UI 截图/测量 `docs/ui/BASELINE_20261026.md` 属于 `3ce5d930` 历史快照。**本文件是目标/验证协议，不表示新 UI 已实现或真人验证完成。** 权威计划始终是 `docs/PLAN.md`。

## 1. 当前行为与目标边界

- 原生 Chrome 侧栏每次默认 `switch` 工作区；页面仅有 `panel.html` 一份可信入口，`background.js` 对 `SNAPSHOT/MUTATE/BACKUP_*/HEALTH_CHECK` 及 `EV_HISTORY` 检查精确来源 URL、扩展 ID、origin、主框架/浏览器上下文。
- UI-D1 首选将**同一 `panel.html` 作为独立标签页**显示宽版查阅，不增加 extension HTML 路径，不改变服务端、数据 schema、Manifest、写入 API 或网页主机权限；测试必须证明无权限扩大，精确 URL 仍不可加 query/hash。UI-D1 只迁移阅读/管理入口而不拆除侧栏旧功能。
- UI-D2 通过后才替换三导航名称；完整页面操作保留侧栏快捷查看结论、依据、交接，独立资料库链接仍是 link/button，不是 tab。
- 与 UI-D1 无关的 S2/S3/S4/S5、pilot/2、真实消息发送与自动抓取不是本次交付。

## 2. 上下文身份及源数据

| 身份 | 唯一权威 | 作用及生命周期 | 不能做的事 |
| --- | --- | --- | --- |
| `sourceChatKey/sourceTabId` | ChatGPT 对话标签 URL + 浏览器 tab ID，经 `ThreadLineCore` 判别 | 表示用户从哪段对话进入，可读提示；不能因资料库成为活动 tab 被隐式重定向 | 不能充当任何目标课题关联指令；自检须检查该 tab 当前 URL 仍为真实 ChatGPT |
| `viewProjectId` | 仅当前页面内的导航意图＋被后台列出的实际课题 ID | 默认打开哪一课题，可手动修改；不同窗口各自管理 | 不能在各窗口间同步为共享 `lastProject`，不能自动保存或重新关联 |
| `captureRunId` | `ThreadLineCaptureDB` 的采集任务身份、源对话 ID、状态 | 不随视图选课题改变；可 `capturing/error/done`，完整性独立标记 | `done` 不等于已分析、已采纳或已交接 |
| `operationTarget` | 提交时固定的课题、结论、版本、修订及操作 ID，由现有 service worker 复核 | 允许人工确认后写入；未知回执必须先核对再显式处理 | 不从“最近选择”推断；不随 sidebar/library 切换或延迟回包改变 |

跨页面导航可传 `viewProjectId`、`sourceTabId`、无正文的搜索字符串、返回来源表面；不可传采集文本、证据片段、凭据、授权或自动提交目标。意图按**新标签 tab ID** 一次性消费、有时间上限；页面直接打开或意图失效时展示安全默认/明确需选择，不写用户数据。任何用户实际写操作使用具体页面当前选择、来源、版本及后台验证。

## 3. 状态及动作行为矩阵

| 起始情境 | 用户动作 | 预期行为 | 失败/退出 |
| --- | --- | --- | --- |
| 侧栏无当前 ChatGPT 对话 | 打开资料库 | 宽页仍可查已有课题；来源标“未指定” | 不自动找一个任意对话自检/采集 |
| 当前对话 A 属课题 A | 在侧栏打开资料库并查看 A | 默认查阅 A，仍能手动选择 B | 不改 A 所属课题、不添加 B 关联 |
| 当前对话 A 属课题 A | 切换资料库选择 B 并阅读旧版本 | B 的正文、条件、来源、版本按需只读 | 历史读取必须绑定 projectId+conclusionId，禁止串课题 |
| 同时两个浏览器窗口 | 各自选择课题 A/B | 各自页面选择独立；新页面仅消费为其 tab ID 预置的意图 | 绝不因另一窗口新打开而改变视图或写入目标 |
| 从 A 采集开始 | 切换资料库看 B | A 的 `captureRunId`、源对话身份不变 | 后台返回晚到不会污染 B 的摘要或草稿 |
| 正在编辑 A 的交接预览 | 切到 B 再返回 A | A 的草稿保留，B 看不到 A 草稿 | 不把 A 的复制、已读写成 B 的回执 |
| 面板中发送写请求 | 用户迅速切课题，回执后来 | 回执仍归属于原对象；新页面选择不回退 | 无法确认时明确“未知”，不能自动重复写入 |
| 通过导航意图打开宽页 | 意图超时/错误或课题已删除 | 不自动选另一个课题代替原任务；提示需重新选择 | 仍可安全地只读导航列表 |
| 资料库为活动标签 | 点击网页自检 | 需显式指定可验证的 ChatGPT tab ID/URL | 禁止针对扩展标签或静默改为另一聊天 |
| 正在 Fork 多分支对照 | 查看进度/进入研究工具 | 只链接既有 `ff.html`，不重建存储/发送 | 未知状态不重发，不在首页伪装 S3 提醒 |
| 备份与恢复 | 打开维护页/执行恢复 | 每份包的包含/排除范围及替换目标就近可见 | 未经确认不执行恢复，首次采纳备份提醒仍有效 |

## 4. UI-D1 验收用例与可执行阈值

- 旧三导航和原侧栏操作**必须保持可用**，UI-D1 只新增入口与适合宽视口的展示。
- 单独宽页打开后可查课题列表、基于现有 `ThreadLineEvidenceList` 搜索全文/条件/编号、可阅读正文、依据片段、旧版完整正文/适用条件/来源；同一项目下严格绑定 ID；不改写真实历史。
- 同样条件下测试 0、1、10、50、200 条，包含相同前缀、撤回、多个版本；旧版 50 条真人判据为 4/5 于 30 秒内找到正确依据，新增 200 条建议预注册为 4/5 于 60 秒内找到正确依据。**尚未实测，不声称达标**。
- 完整权限负例：无效 `sender`、query/hash 变体、其它 extension origin、iframe、伪造 tab ID 应被拒绝；真实 `panel.html` TAB 顶层与 SIDE_PANEL 合法；不为宽页加入通配消息源。
- 消息请求晚返回、搜索条件变化、切课题、刷新/关闭/恢复、两窗口并行、取消与未知回执都要覆盖；页面不会把库 tab 当 ChatGPT。
- 320/360/480/768/1280 CSS px 无丢正文与必要动作，键盘可到达、焦点可见，读屏真人至少一个核心任务。视觉/DOM/自动化/真实登录/真人任务分别登记，不能相互冒充。
- 若存在错误课题写入、错误来源匹配、静默丢草稿/版本或未授权发送，则阻断任何合并和 Release。

## 5. 方案依赖与未来决策

- UI-D0 先单独提交 `docs/PLAN.md` / `DESIGN.md` 和本契约供人工治理复核，非正式机器 `done`。
- UI-D1 在独立候选 PR 上实施；CI 包含准确 HEAD 的 Node、Chromium MV3、Windows。用户可在隔离浏览器使用，不在现有用户数据上测试破坏性操作。
- D1 通过后独立评审 UI-D2，再决定默认侧栏从三个标签收敛到两个，避免未经验证地一次搬空原侧栏。
- D3 向宽页迁移备份/维护可能扩大受信页面范围，须按 L3 评审后做，不能以 L2 的“重排布局”名义绕过权限。
- 试点 `threadline-s2-pilot/2` 使用的 UI commit SHA 必须在协议冻结前记入，试点运行中不换 UI。
