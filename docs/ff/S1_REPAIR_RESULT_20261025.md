## 已落实的修复

| 原发现 | 当前实现与验证边界 |
| --- | --- |
| R01 面板崩溃 | 修正 DOM 元素名称的字符串；实际 MV3 面板显示含会话身份的来源与修订控件。 |
| R02 操作台账 | snapshot 按 operationId 索引；请求摘要绑定命令和完整规范化输入；事务先查台账再做 CAS；浏览器重启后同请求返回原结果。旧摘要格式明确要求人工核对，不自动重放。 |
| R03 导入覆盖 | 校验包容量、四类 ID、引用/归属/前驱链、状态、哈希和限额；版本/来源/链接以 add 写入单事务。导入摘要覆盖完整原始包，派生去重缓存不作为可信事实。 |
| R04 接管丢失 | 导出 `/2` 保留 takeover 与未验证 legacyNote；兼容读取 `/1`，缺少的历史信息明示 unavailable。恢复正式结论始终封口旧 decision；不导入其他设备的运行台账。 |
| R05 危险删除 | 后台同一串行段检查并拒绝删除、clearClosed、旧恢复/回滚覆盖或遗漏已接管课题。此为风险封堵，完整删除与墓碑协议仍未交付。 |
| R06 权威缺失 | 独立存储标记与权威库不一致时明确失败；不重建空库冒充有效状态。检查当前版本和来源引用；初始版本至少一条依据，新版本记录 sourceCount 检测引用数量丢失。故障数据可通过诊断命令原样导出，不自动清洗。 |
| R07 单向投影 | 由 IDB 重算 decision、knowledgeVersion、history 和摘要，在一次 chrome.storage 写入中登记投影修订；重复对账不重复升版本。投影失败仍保留已提交证据并返回 pending。 |
| R08 旧表单封口 | decision 显示只读；改名、目标、收口不再夹带 decision。后台继续拒绝绕过 UI 的直接改写。 |
| R09 来源去重 | 指纹包含来源身份、关系、完整性、条件与摘录；按规范化来源排序。原型表单不再将每次点击时间作为新来源身份，反复点击不增加结论。 |
| R10 修订保真 | 只改正文保留条件、来源 ID、采集时间/类型/运行/URL；旧版本不可变。面板携带已读版本，另一窗口更新后拒绝过期修改。 |

交接改为可编辑预览后显式复制；生成和复制前读取权威版本。证据变化时拒绝复制旧预览，保留用户草稿并给出提示。它不自动发送、不推断模型已理解，也不是完整的交接审计记录模型。

## 独立审查及处置

核心存储审查与整合审查均由只读代理执行，ROOT 逐项核对后修改。整合轮确认四项：空包导入导致错误接管、依据链接全部丢失未检出、复制提示调用不存在函数、原型重复点击生成新时间导致重复采纳。均为 CONFIRMED，修复并补失败场景回归；无未决争议。空包在预览/导入前拒绝，不写入接管标记。

治理测试由硬编码 12 项 done 调整为明确的 8 项历史 done、4 项 blocked 及阻塞文档路径，与已核实的 PLAN 状态一致。生产检查器、工作流、阶段完成条件及历史证据 JSON 未放宽。
