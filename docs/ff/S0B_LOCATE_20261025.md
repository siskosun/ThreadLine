# S0b 来源定位 spike：三方案比较与采纳结论（2026-10-25）

时间盒：约 4 小时有效工作（上限 8 小时）。范围：把“来源结论→定位到具体消息”的滚动/虚拟列表定位能力选定一条实现路线；不为比较而实现三套（依据 REUSE_AUDIT_20261024.md §3/§4 的先复用原则）。

## 三方案实测比较

| 维度 | A. 仅用现有适配（capture-core 的 DOM 行走） | B. Toolkit 固定提交子集（vendor） | C. 最小本地实现（约百行滚动定位） |
| --- | --- | --- | --- |
| 反向滚动（column-reverse 负 scrollTop）坐标 | 无此能力（采集是顺序读 DOM，不做定位滚动） | 上游已验证的坐标数学 + 三个行为测试（反向坐标/负原生位置/普通坐标） | 需自研并自证，虚拟列表回归面大 |
| 接入成本 | 0（但缺能力，等于不解决） | 裁剪后 vendor 87 行 + 注入式适配器（locate-adapter.js 96 行） | 估计 100–150 行新代码 + 自建测试 |
| 全局状态耦合 | - | 已移除：滚动根由注入 `resolveScrollRoot` 提供，上游宽泛兜底（可能误选侧栏）不带入 | 需自行处理滚动根选择与侧栏误选 |
| 测试 | 无 | 上游三用例移植为 `test/toolkit-scroll.test.js`（针对**本仓 vendored 文件**运行，非另写模型）+ 身份/取消/弱匹配 4 用例（共 7，224/224 全绿） | 需从零建测试，且缺上游实测背书 |
| 维护 | - | 上游 pinned commit 不自动跟随；升级=比对差异+许可+跑本地契约测试 | 全部自维护 |
| 许可 | - | MIT 已登记（licenses/MIT-GPT-Conversation-Toolkit.txt + THIRD_PARTY_NOTICES.md，含上游 SHA/符号/改动/测试说明） | 无外部义务 |

## 结论

**采纳方案 B**：`vendor/toolkit-scroll.js`（上游 `utils/dom.js` + `features/virtualized-jump.js` 的坐标算法，pinned `119d3728`，滚动根注入化改造）+ 自研 `locate-adapter.js`（ThreadLine 语义层）。

- 降级路径保留：`locateMessage` 的弱文本匹配永远返回 `verified:false, weak:true`，调用方必须显示“仅片段”而不跳转——符合计划 §十一.4 的降级要求。
- 身份契约：优先 `data-message-id` 精确匹配 + 角色/内容前缀复核；不一致即 `located:true, verified:false`（不冒充定位成功）。
- 取消契约：`AbortSignal` 协作取消，等待虚拟渲染的重试循环可随时中止（测试验证未跑满预算即停）。
- 明确不移植：上游私有会话接口、页面响应拦截、认证处理、命令式 virtualizer 全量跳转模块（`conversation-index.js` 等不加载）。

方案 A 不成立（无能力）；方案 C 被否决：坐标数学是已验证的难点，重复实现只增加无背书的回归面（违反审计 §3“不为比较各做一套”）。

## S1b 接入点（后续）

- 整理记录与 Fork 揭盲的“查看依据”按钮 → `locateMessage(document, {messageId, role, contentPrefix}, {adapter, signal})`；`verified:true` 才 `scrollNodeIntoView`。
- 滚动根探针由研线现有选择器逻辑提供（chatgpt.com 主对话区），不使用上游兜底。
