## 二、真人旧数据与 L3 风险门禁（PR #36/#39）

1. **先由用户本地完整备份原浏览器 profile 和证据库。** 公共 GitHub 不接收账号、原始对话、Cookie、会话 ID、截图或未经脱敏的备份；切片只可在另建的隔离浏览器配置安装。不得用旧版扩展写入新版 `threadline-evidence/3` 资料。
2. 以一份脱敏的旧 schema（包括 /1、/2、只读旧 decision）验证升级、重启、重复相同操作 ID 的幂等；过期窗口修订拒绝覆盖；损坏来源、截断包、冲突链接和旧恢复遗漏课题等危险输入被保守拒绝。
3. 在用户明确授权的隔离配置完成 12 次有效“选证、核对、采纳、失败重试”完整任务，≥11 次无帮助，耗时中位 ≤30 秒/P90 ≤60 秒，至少 4 次由非设计者操作。自动点击/毫秒级事务链路数据不算真人耗时。
4. 只有完成适用 L3 人工风险评审和 README/回滚说明后，所有者才能在**精确 PR HEAD**下亲自留言：`MANUAL_ACCEPT <TASK_ID> <PR_HEAD_SHA>`（见 [EVIDENCE.md](EVIDENCE.md)）。Agent 不代签；若提交 SHA 改变，旧评论不用于新 HEAD 认定。保存脱敏验收范围，并按治理流程登记 `docs/ff/evidence/<TASK_ID>.json`。

## 三、F3 真人 ChatGPT 采集（PR #40）

**线上原故障仍是 OPEN：** 2026-10-24 K=4 真人 A/B 点击“采集回复”无推进、无错误（[历史证据](evidence/P4-LIVE-K4-V080.json)）。新代码仅证明旧后台会吞启动/关联错误，**不能据此认定当时真实根因已定位或线上 F3 已修复**。

- 将 F3 修复候选安装在隔离的真实已登录浏览器配置。只在人工明确允许后运行普通 ChatGPT 会话操作；所有消息发送保留人工动作。检查 A/B/C/D 全部有效分支与确切来源会话是否一一对应。
- 按 [PLAN §12.4](../PLAN.md) 在**至少三个不同自然日合计至少 12 次**实际端到端尝试（每天覆盖 K=4），含采集 → 对照 → 裁决 → 导出 → 导入；保留逐次结果和精确构建 HEAD。12 次是工程冒烟门槛，不能推算上线成功率。
- 每次采集使用 `FF_CAPTURE_STATUS`（由扩展 Fork 页面按同一实验/分支/运行 ID 查询）记录 `started`、`runId`、`captureStatus`、`branchPhase`、`ageMs`、`error`。不要公开会话原文/完整 URL。出现 `stalled` 是 30 秒未更新警告，不表示操作肯定失败，禁止自动重复发送。
- 分别演练一次选择器失效降级，以及 MV3 Service Worker 中止/恢复（已有原始记录不可静默覆盖、未知状态不能自动重放）。如果持续遇到 429 或人工门禁未满足，登记 `BLOCKED/NOT_EXECUTED`，不伪造通过。只由所有者或明确授权真人验收真实站点。

## 四、S2–S5 产品可行性与发布裁决

1. 先通过 PR #45 建立有人工独立真值的六案例/三臂 `pilot/2` 冻结协议。每例 ≥5 预定义变化事件，总数 ≥30；至少两例独立双人标注，真实 A/B/C 完整记录。
2. B 的影响集合只能由与线上相同的 `ThreadLineResearchCore.impacts` 实算，不接受从评估者填入预测；按照案例聚类报告描述性区间，不能拿 30 事件当 30 独立案例。
3. 根据可行性结果和工程安全线选择：继续 Draft、隔离但默认关闭、或停止继续投入，不为了代码已写就发布 S2–S5。需要实际结果证明对正确接续、误改和人工工作量的价值，不能以绿 CI 代替用户收益。
4. 即使逐个 PR 最终获准合并，也须**默认禁用 S2–S5** 或保持隔离测试配置：界面隐藏不足以禁用后台命令/数据写入/自动触发。发布前检查 ChatGPT 原生功能重叠与最新 DOM 兼容。未经用户明确批准不得执行 GitHub 合并、发布新 Release 或更新用户安装。
