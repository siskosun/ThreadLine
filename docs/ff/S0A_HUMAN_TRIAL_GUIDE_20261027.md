# S0a 人工采纳试次：执行与证据核验指南（2026-10-27）

本文件只描述可执行的人工验收程序，**不表示试次已发生**，也不修改 `docs/PLAN.md` 的 S0A-PROTOTYPE（blocked）状态。

## 现有误差及范围

- 原原型的“自动执行 12 次计时协议”量的是 Playwright/按钮点击至 IndexedDB 提交回执的延迟，曾测得毫秒级时间。此结果可保留为**合成写入性能基准**，不能据此声称真实用户在 30/60 秒内完成审阅或补证。
- 本次保留原自动化和历史 S0a 证据，不篡改旧收据；新增独立人工试次入口。两类输出的 `protocol` 和 `mode` 不同，统计不合并。
- 只用虚构的线路 A/B 转化率材料、一次性浏览器测试配置及新建 `proto-human-*` 课题。**不可在现有真实安装目录运行，不输入真实用户数据**。
- 不增加 ChatGPT 网页权限或发送行为；后台 `EV_ADOPT` 仍由 service worker 单一写入。

## 操作步骤（真实操作者执行，不由自动化代签）

1. 在**新建且无业务数据的浏览器测试配置**中加载此 PR 版本研线扩展；通过 `chrome://extensions` 的扩展 ID 打开 `chrome-extension://<扩展ID>/evidence-prototype.html`。无须登录 ChatGPT。
2. 展开“人工采纳试次”。填写匿名操作者代码，例如 `P01`；是否为设计者按事实勾选。不要填写姓名、工号、邮箱等个人信息。
3. 点击“开始下一项人工任务”。开始计时后按要求核对原文，直接采纳或修订/补证。第 1–6 项是直接采纳，第 7–9 项须纠正故意写反的结论，第 10–12 项须增加缺失的证据。**有求助就勾选，不要为追求数字而隐瞒**。
4. 核对后勾选“已核对采纳结果与任务要求”，点击“保存本项人工试次”。计时从材料展示到持久化回执，包括阅读、修订、选证和重试前的核对。无法完成时点击放弃；结果未确认时记 `unknown`，**禁止自动重放**。
5. 12 项全部完成后点击“复制脱敏人工记录”；只提供试次类型、匿名代码、是否求助、自报核对、结果、耗时、操作 ID、时间和汇总指标，**不包含结论正文、原文片段或聊天记录**。保留原始匿名日志供独立核查；不用公开 GitHub 当作个人操作数据收集端。
6. 由独立审查者复核操作身份、任务实际完成情况、帮助记录与写入对应关系。发现操作失败、语义错误、误标“非设计者”、结果未知或无法追溯时，不认定为有效人工成功；保留失败和未知数据，不事后删除或修改门槛。

## 预设验收口径（不自动签署）

- 必须有 **12 个不同案例、6 次直接采纳、3 次纠错、3 次补证**；出现遗漏、重复或不符合类别均为证据不足。
- 记录内 12 项均有有效提交回执及操作者核对；至少 **11 次无需帮助**；至少 **4 次由非设计者实际操作**。
- 有效任务耗时中位数不超过 **30 秒**、P90 不超过 **60 秒**。P90 使用 nearest-rank；偶数样本的中位数取中间两项平均，统计输入及失败/剔除范围需明示。
- UI 可以计算上述数字是否达到，但**始终返回 `HUMAN_REVIEW_REQUIRED`，不会自动将 S0A 标成 `done`**。操作者是否真人、答案语义是否正确等无法从脚本证明，须独立人工观察和签署。
- S0A 原计划的事务、崩溃恢复、限额及风险评审条件依然独立有效；此记录不能替代全部 S0A 验收或 S1A/S1B 的数据安全与真人闭环。

## 测试与限制

- `threadline-extension/test/s0a-trials.test.js` 检查统计、重复案例、伪造“合成结果”、未知回执和未达标不放行。
- `test/evidence-e2e.py` 仅使用一次性 Chromium MV3 配置**模拟点击**来验证人工记录器是否能保存和导出；该自动化烟测**不是人工操作证据**。
- 真实用户操作、4 次非设计者任务、真人是否受帮助、正式工效数据均为 **NOT_EXECUTED**，不得引用自动化通过替代。
