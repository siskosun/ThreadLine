**范围：修复既有 S1 契约，不启动 S2。** 已批准的第十一节目标继续有效。本次新增的是具体恢复兼容策略、历史受损记录处置和危险操作的临时限制；这些属于 L3，不能用旧的有条件计划评审或内部审查替代本次 Gate。事实来源：[复验记录](ACCEPTANCE_20261025.md)，main `f43fd072eb6f85dc78bddcc9853899c103293b73`。

## 1. 先保障持久操作与导入完整性（R02/R03）

- 修正真实 snapshot 的 operationId 映射；后台在内容去重前检查操作台账。同操作同规范化请求返回原结果，同操作不同请求拒绝。摘要覆盖命令类型及完整用户请求；首次从旧库提取的 legacyDecision 是服务端上下文，不能让重试因该值改变而变成新请求。
- 导入摘要覆盖完整包内容，而非仅 projectId/exportedAt；先处理操作重放，再检查已存在记录。所有新建版本/片段/链接采用禁止覆盖的事务写入或等效事务内冲突检查；CAS、台账和业务修改同事务提交。
- 导入验证所有数组、字段类型、ID 格式、包内重复与全库冲突、版本/当前版本/前驱链归属、链接两端、来源哈希、枚举、计数与累计容量。包内引用必须完整，不默默依赖另一课题的已有对象。异常整包拒绝，不部分恢复。
- 所有读当前正文的路径按 currentVersionId 读取，不能以 createdAt 排序猜当前版本。相同时间戳也必须正确。
- 旧台账摘要格式不能悄悄改义：旧操作用兼容验证或明确拒绝并要求人工核对；不自动重放，更不自动发送。具体兼容方式是本次 Review 的必答项。

## 2. 恢复必须保留接管语义（R04/R06）

- 提议新的导出格式 `threadline-evidence/2`，保留结论/版本/来源/链接及必要课题元信息（takeover、未验证 legacyNote）；不导入其他设备的投影队列或幂等运行台账。数据库 schema 无需为可选字段升版。
- 保留旧 `/1` 读取：有正式结论即必须接管；旧包没有的 legacyNote 标明“旧格式不含”，不编造历史。已有本地 legacyNote 不静默覆盖。导入预览明确格式、原文片段、条数、丢失的旧元信息和冲突，用户确认后再提交。
- 从旧版本导出前先验证引用与哈希，发现已受污染数据则显示诊断并允许另存原始故障备份；不以“清洗”名义删除或覆盖现有记录。现有数据损坏修复另需可审阅映射与用户选择。
- 投影/接管记录显示曾有证据，但 IDB 缺失、损坏、读取失败时必须显式报错，阻止依赖旧 decision 的写入、交接和删除。首次使用的正常空库与已接管库丢失分开。跨库“提交后投影前全库丢失”能否可靠识别必须在方案中声明；不能承诺两个数据库不存在原子性窗口。
- 对已发布 `/1` 包兼容、扩展回退版本的读取能力和原始备份保留作 L3 风险确认。若外部评审认为新增格式不必要，可改为向后可读的可选元数据方案，但必须说明旧客户端遗漏元数据时的限制。

## 3. 危险删除/恢复先保守拒绝（R05）

- 第一批修复暂时禁止删除已有证据的课题，以及旧 BACKUP_IMPORT/BACKUP_ROLLBACK/clearClosed 等会覆盖或移除已接管课题的操作。检查当前集合与目标集合的差集，且检查与变更在同一后台串行段，不能检查后再入队产生竞态。明确错误及导出/保留指引，不显示删除成功。
- 完整“删除正文+副本、保留无原文墓碑、跨库幂等恢复”是下一批任务；在其完成前，D3/D5 仍不算通过，不将临时禁止伪装成完整删除功能。不删除已导出的外部备份。
- 只有明确用户删除意图才允许完整清理；unknown 请求先查询原操作结果。浏览器整体关闭、SW 中止和 chrome.storage 失败逐点注入。

## 4. 把兼容显示与来源身份接回权威库（R07–R10）

- 由已提交 IDB 重算旧 decision、knowledgeVersion/历史和独立摘要；在同一次 chrome.storage 状态写入中记录已投影 evidenceRevision，重放相同修订不再次提高版本。投影未完成要可见，不能标成最新；交接读取权威版本。
- 接管后旧编辑框只读，保存名称/目标/收口时不提交 decision；后台仍拒绝直接写 decision。刷新与重开面板后的行为一致。
- 来源去重指纹包含稳定来源身份、摘录、关系及条件；不同来源的同文摘录不能误合并。引用顺序归一化的规则在实现前冻结。无可靠来源身份仅能按明确的人工输入记录处理，不伪造“完整原对话”。
- 仅修改正文时保留条件与既有不可变 SourceSnapshot 引用；显式换依据才新建来源快照，原 capturedAt/kind/captureRunId/url 不变。修订对外语义与旧包版本链一起验证。
- 逐条采纳的普通整理入口、Fork 长回复的完整性标记与来源 ID 属于第二批 S1 完成项；与主存储修复分开评审，但未完成前 S1B 不恢复 done。
