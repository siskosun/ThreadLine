复核材料可以复制到用户选择的新对话，发送与分析由用户决定；不会自动重放旧动作或发送模型请求。这一设计不宣称严格盲测：用户可能已经读过旧结论。复核结果只代表对应范围的人工判断；采纳、复核保留和事实已证实不是同一回事。

## 存储与恢复约束

- service worker 串行队列 + IndexedDB 单事务 CAS；Conclusion、Version、Source、Link、project revision、操作台账一起提交。`chrome.storage` 摘要只从权威库重算。
- 删除与替换恢复绑定完整预览及操作请求。提交丢响应时可用同一请求重试，改正文、选区、课题信息或预览后不能复用旧 ID。来源缓存过期不妨碍已提交采纳的幂等回放。
- 删除保留无正文墓碑；清理本课题证据、交接/复核记录、操作响应里的原文、摘要及撤销副本。独立采集缓存、Fork 原件、剪贴板及外部文件在删除提示中列为保留范围。其他课题仍引用的源快照保留。
- 替换恢复会删除当前课题状态，界面明确要求先自行导出。恢复意图先入权威库，课题元数据和摘要可在重启后继续恢复；恢复 revision 高于仍存的摘要标记。整个数据库丢失时，必须恢复全部已接管课题，不能让缺失的课题静默变成空白。
- 备份 `/3` 包含研究和交接历史，仍读取 `/1`、`/2`。普通追加导入不能覆盖已有研究历史；替换仅经明确恢复流程。保存前复用完整导出校验，防止已存记录无法导出。
- 单课题可恢复包 20 MiB、全库 100 MiB；200 个结论、每结论 50 个版本、每条 8 个片段。复核最多 63 份来源，另加问题；交接 128 KiB，历史 100 条。超限报错，不截断或自动淘汰。

## 依赖与复核语义

依赖连接稳定结论 ID。确认历史保存上下游版本、边 epoch、材料范围哈希、理由与覆盖的变化事件。正文改版不增加边；只推进用户明确确认的版本。仅措辞承接只改下游版本指针，保留旧上游指针，不能消除尚未核对的上游变化。

变化提醒来自已登记图，不代表真实依赖已全部登记。目标撤回或明确移除相关路径可解除当前提醒，历史仍可读；重新启用的边不能继承旧 epoch 确认。传递影响需要目标对应的人工核对，不因中间结论正文没变而自动消失。

复核准备时冻结全部祖先结论、状态、边及来源。期间新增/删除关系、修改版本或撤回会使完成结果仅留历史。当前保留可推进精确范围内的确认；修订生成新版本，撤回保留历史，无法判断不关闭待核对项。交接文本同时列直接和传递待核对项，其有效性绑定依赖/确认及版本，复制与人工看过分别留记录。

## 开源复用

直接复用 MIT `@argdown/core@2.0.1` 的官方 ParserPlugin / ModelPlugin，固定锁文件，使用 esbuild 生成符合 MV3 CSP 的静态包。没有自写 Argdown 解析器或打包完整编辑器。`npm run check:argdown-build` 不修改源码，逐字验证已提交 bundle；LF 属性保证跨平台一致。第三方许可见 `THIRD_PARTY_NOTICES.md` 及 vendor notices。S0 定位仍沿用已审计适配与失败降级，没有把整个 Toolkit 注入页面。

## 验证与复审

验收命令：`npm ci`、`npm run verify`、`npm run test:e2e`、`npm audit --json`、`python scripts/build-release.py`。verify 包含语法、版本、计划契约、Argdown 构建一致性及单元回归；E2E 包含七套一次性 Chromium 配置，全部使用合成数据与拦截页面，不访问真实账号。日志、运行版本、退出码、源码前后指纹与 SHA-256 清单随候选交付。

首轮独立 LOCAL_PRE_REVIEW 的七项发现均由 ROOT 复证并修复：删除台账残留、恢复替换不可达及误导文案、粘贴选区失败、Argdown 旧候选确认到新版本、畸形变化路径导入、交接遗漏传递影响/范围变化、64 来源导致保存与导出契约不一致。补充原生全库删除扫描、操作请求变更拒绝、多个课题丢库恢复、候选过期、来源回放、路径校验和有效性测试。第二轮又发现首次提交没有绑定恢复文件/删除目标的预览漏洞，已增加完整备份哈希和课题一致性校验；原两反例在复证时均于写入前拒绝。第二轮定点复验报告 NO SUBSTANTIVE FINDINGS。复审不替代 ROOT 运行验证，也不冒充外部 ChatGPT Gate。

全局 verify-run helper 因未签名策略未执行；不绕过该策略。直接命令收据和 GitHub CI 是原生验证证据，不标为 helper FRESH。正式 done 的旧 PR/签署验证保持；新增 S2–S5 ID 仅扩展机器登记，未放宽完成条件。

## 试点与应用边界

- **OPEN_UNKNOWNS：** 六真实案例效果、至少两例第二人标注、真人摩擦、真实站点 F3 采集停滞、既有用户库历史损伤。均未从合成测试推断通过。
- **ASSUMPTIONS：** 扩展 IndexedDB 可用；用户保留备份并确认来源/依赖；自动提醒覆盖已登记关系。
- **DISPUTED_FINDINGS：** 本地实质发现已采纳，无未决高风险争议；未知项保持未知。
- **IRREVERSIBLE_EFFECTS：** 本轮没有触碰用户安装或数据库。未来用户点击删除/替换可能删除当前原文，外部文件不能收回；正式应用需验收这一边界。
- **ROLLBACK_STATUS：** 代码可回退。新版 metadata 不应由旧版扩展再次写入；先导出完整 `/3` 备份，在隔离配置验证恢复。不能把旧版忽略新字段称为数据回滚。

`scripts/evaluate-dependencies.mjs` 只由录入边调用相同 `Research.impacts` 计算预测，不接受人工填入 predictedAffected。输出输入哈希、协议版本、TP/FP/FN、漏路径、完整率、超过三条前提的比例及日志耗时；模板明确为合成数据。正式试点仍按 PLAN 的 90% 完整率、90% 召回、80% 精确率、关键漏报 0 和 15% 配对耗时改善等预注册条件另行执行。
