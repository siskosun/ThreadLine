# ThreadLine UI 与交互评估、优化记录

本轮以 `848d06c` 为基线，按用户要求先验证、再自行迭代，并评估所有现有界面与操作入口。基线的 290 项单元测试、7 套一次性 Chromium E2E 及准确提交的 Linux/Windows CI 均通过；测试通过不代表界面已经易用。本轮对实际渲染截图和真实扩展页面上的控件继续检查。

## 本轮改进

原界面把证据库放在两大工作区和页脚之后，新增研究控件未统一应用表单样式，窄侧栏中容易出现连续小控件、重复正文和难以辨认的输入框。现在按任务分为“对话切换 / 研究整理 / 证据与复核”，进入证据页会刷新课题目录，新建课题无需重开面板。依赖、局部复核和 AI 建议按需展开，不增加全局大画布。

采纳窗口会等到保存或取消才返回结果，不再提前报告“已提交”。切换原始消息时清除旧选区；手工修改片段会清除旧坐标。失败保留输入，同一内容的显式重试复用同一操作标识。修订使用一个完整表单展示正文、条件、变更类型与承接选择，替代连续原生 prompt。按 Escape 或取消会清理窗口并尽量恢复原焦点。

研究、备份和 Argdown 工具增加响应身份校验，旧请求不能替换新课题或新文件的内容；自动刷新保留正在填写的分析、理由和依赖选择。操作完成后的反馈不再被目录刷新覆盖。已经完成的复核以历史方式打开，提交按钮禁用。Argdown 导出缓冲在课题或版本变化后清除；导出与导入区分别有可见标签。

交接草稿按课题保存在当前面板内存中。生成时冻结课题和编辑代次，切换课题或继续输入后，旧回包仅保留后台历史，不覆盖当前草稿。复制、人工看过分别绑定点击时的文本和材料身份。关闭面板不会自动持久保存未提交的编辑草稿；需要保留时应先复制或导出。

Fork 页面按实际 2–4 分支显示操作文案，避免“多分支已创建”仍提示“两条”的歧义。分支状态显示中文；异步读取列表/详情有代次校验。定时刷新保留裁判选择，切换实验保留各实验尚未提交的裁决草稿。发起按钮保持后台状态决定的禁用状态，导入先检查 20 MiB 文件上限再读取。

## 复审发现与修复

| 发现 | 失效方式 | 修复与回归 |
| --- | --- | --- |
| 复核正文修订清空条件 | 新增条件框为空时无条件提交，用户只更正正文也会删除原条件 | 只有用户实际编辑过条件才提交该字段；没有显示旧结论也能保留原条件，显式清空仍可生效 |
| 旧复核回包进入新表单 | 等待准备/旧参考时切换同课题目标，旧内容可能填入新目标的修订框 | 按课题、目标、复核 ID、窗口代次校验；手工编辑过的字段不被参考回包覆盖 |
| 旧交接覆盖未保存草稿 | 生成 A 时切到 B 或等待中输入，旧回包替换当前内容 | 独立生成/编辑代次及课题草稿映射；旧结果只留历史；重复点击只发一次准备请求 |

以上三组实质发现经 ROOT 复证和修复；本轮独立 LOCAL_PRE_REVIEW 进行了原生反例复验，最后报告 `NO SUBSTANTIVE FINDINGS`。这是一轮本地复审，不冒充外部 ChatGPT Gate。最终验证仍绑定最终源码快照，运行过程中修改过源码的测试日志只保留为过程证据。

## 布局、键盘与视觉复核

在 320、360、768、1280 CSS 像素宽度下检查页面横向溢出；窄侧栏中控件统一为单列，字段具有可见或程序化标签、焦点样式和只读状态，长回复和历史在自己的区域换行/滚动。主导航采用单一 Tab 停靠点及左右/Home/End 键；原生 dialog 提供焦点范围和 Escape 取消。

对空态、已采纳结论、工具展开及 Fork 表单生成优化前后截图，并逐张检查真实渲染。截图使用虚构材料，随交付保存，不包含用户对话。本轮没有宣称通过正式 WCAG 认证，也没有把机器点击耗时当作真人易用性数据。

## 最终检查与剩余边界

最终命令为 `npm run verify` 与 `npm run test:e2e`，后者纳入新增的第八套 `ui-interaction-e2e.py`。最终日志、退出码、源码前后指纹、准确提交 CI、候选包内容核对与 SHA-256 清单随本轮交付。没有修改权限、证据存储 schema、正式 done 门槛或自动发送原则。

仍未执行真实登录网页操作、远程模型/Ollama 调用、真人工效与六案例收益试点；历史 F3 的真实环境问题仍待实际环境复现。当前可交付的是经合成数据与跨平台检查验证的优化候选，合并、发布和用户库正式应用保持独立。全局 verify-run helper 受未签名策略限制，原生命令收据不标为 helper FRESH。
