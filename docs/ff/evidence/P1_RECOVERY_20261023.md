## Confirmed findings and fixes

1. **Saved create + display error:** old UI cleared its intent on successful FF_CREATE before subsequent FF_LIST/FF_READ. A failed display followed by unchanged-input manual retry produced two records. The lease now remains until both display operations succeed; the notice identifies an already-saved result. Same-tab reload keeps the original operation ID. A busy flag prevents reentrant submits. No automatic retry; a completely displayed success ends the intent and a subsequent explicit save may create a new experiment.
2. **Attempt identity:** an established session ID cannot be changed by later events, including pending/failed/unknown/done. Events omitting identity preserve the binding in the existing evidence object. Explicit new attempts can bind their own identity, preserving history.
3. **Completion signal kinds:** accept only strings generation/stable/final and at least two distinct recognized kinds. Invalid primitives, objects, unknown names or a single repeated kind cannot count. These are upstream attestations, not measurements performed by the pure core; P1 dispatcher still rejects done and webpage evidence.
4. **Reducer baseline:** retain the original JSON snapshot before the reducer, reject mutation even when returning the prior object as a purported no-op, and compare resulting id/revision/frozen data against the saved baseline. Pure stale idempotent replay remains valid. Current production reducer already clones its input; this closes the internal guard gap.
