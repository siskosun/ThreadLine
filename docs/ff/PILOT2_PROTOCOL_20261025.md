# Pilot/2 研究接续三臂可行性筛选（2026-10-25）

**状态：协议与评估器工程候选；真实研究执行 NOT_EXECUTED。** 与已存在的 \`threadline-s2-pilot/1\` 并存，不篡改原协议、门槛或历史记录。

## 研究问题

在同样研究资料、模型可用条件和预算下：S1+S2/S3/S4 的定向核查（B）相对已有 S1 流程（A）以及在新 ChatGPT 对话直接重做整个问题（C），能否减少错误接续、错误修订和人工操作时间？只做可行性筛选，不声称因果、普遍效益或统计验证。

## 预注册和原始真值

1. 在 **任何三臂运行前**，由人工形成 6 个不同脱敏研究案例，每例至少 5 个预设变化事件，共至少 30 次，包含关键前提错误、指标口径变化、来源丢失、仅措辞变化和无关分支。
2. 人工独立标注必要边、每事件影响集合及关键实质错误；六个案例每例至少一份原始标注及 `annotationSha256` 收据，至少 2 个案例由两人独立标注、各自保留不同原始文件 SHA-256。双人案例还须记录 `adjudication.resolvedAt/reviewedBy/resolutionSha256/disagreementsResolved`，两份原始提交均早于分歧裁定，分歧裁定早于协议冻结。哈希用于人工追查原件，脚本不能仅凭格式证明标注者实际独立或裁定真实发生。不得从工具运行的预测反向标注真值。
3. 三臂顺序交叉，控制可见资料、模型版本、预算；C 臂给模型相同原始材料与研究问题，让其自然直接重做。记录模型调用、工具调用、全部人工核查/恢复耗时，不允许只统计成功点击。已学习正确答案的操作者不得被悄悄重用为独立样本。
4. 每事件预先登记相同原始资料的 `sourceCorpusSha256`；A/B/C 各自收据必须证明引用同一份原始资料和模型版本，不得重复使用收据。**禁止自引用提交哈希**：`freeze.commitSha` 必须指向已经存在、独立审定的前置输入/规则 Git commit（40 位 SHA-1），不是将来存放 FROZEN JSON 的那个提交。先以 `status:FROZEN`、冻结时间、前置提交 SHA、规则哈希、预审人员生成协议文件并计算其原始字节 SHA-256，再将文件作为新提交写入 Git；最后在独立的审核记录中同时记下协议文件 SHA-256 与实际存放文件的提交 SHA。原始协议不再回写后一个提交 SHA，避免循环哈希。冻结后改动任何协议字节须新版本预注册，不得拼接不同版本。
5. 与协议分开保存观测 JSON；只有在全部真实操作、原始脱敏收据和所有三臂记录齐全后标记 \`status:EXECUTED\` 并填 \`protocolSha256\`。模板刻意写入 NOT_EXECUTED，不可直接当数据使用。

## 预冻结的分层规则与增量指标（2026-10-26 修订；仍未执行）

该修订必须在 `threadline-s2-pilot/2` 首次 SHA-256 冻结之前进入协议与评估器。**没有真实标注、实测日志或冻结收据，不能称为筛选通过。**

- 冻结协议增加 `tierRuleId=threadline-s2-tier/1` 与 `tierRuleSha256`：必须等于 `scripts/pilot2-tier-rule.mjs` 的准确文件字节 SHA-256，并由人工确认在分析/观察工具输出之前签署 `ruleFrozenBeforeScoring:true`；**这仅是可审计的声明，必须有独立时间/提交证据，布尔值本身不能证明盲法执行。** 代码更改须重签新协议，不能以更新后的规则复算旧试点而冒充预注册。
- **多路径安全门禁**：`Research.impacts` 对同一根结论可能只输出一条代表路径，同时在 `contributingEdgeIds` 留下其他路径的边集合。若不能对全部贡献路径证明符合降级条件，一律归为 `must_review`；不得因代表路径是两跳就隐藏另一条直接必要边。合成图反例纳入自动测试。
- **禁止情景标签泄漏**：`kind=premise_error/definition_change/source_lost/wording_only/unrelated` 仅用于样本构造与人工真值审核，绝不能输入分层规则。纯规则只能使用事先记录的 `observedChangeKind=amend|withdraw`（与 S3 实际 `changeKind` 一致）及下述来源/关系/交接证据；若尚不能证实仅措辞，则按保守规则维持 `must_review`，不得借看过 G* 后的“非实质”标签降级。
- G* 仍由 `goldAffectedIds` 表示每事件真实下游影响集合。每个 G* 成员必须在冻结前以 `goldMateriality[targetId]=substantive|non_substantive` 标注；关键实质错误目标列在 `goldCriticalIds`（为实质 G* 子集）。误报是**不属于 G*** 却被预测的目标，不得伪造“非实质真值”来提高分母。双人独立标注须先于工具输出，分歧裁定及原始标注另存收据。
- 每事件冻结来源状态 `sourceSnapshotStatus=verified|missing|hash_mismatch|unknown`；只有 `verified` 可连同 `sourceSnapshotEvidenceSha256` 的独立材料哈希进入降级规则。当前交接作用范围使用 `handoffIncludedIds` + `handoffScopeSha256` 固定；缺失范围显式为 `null`。**哈希只证明相同字节，不能单独证明来源真实有效**；需要独立人工核对。当前 S3 仅有 `necessary` 边、`amend/withdraw` 改动事件，不得凭空假定背景边或通用 S4 来源状态已上线。
- **不允许免费输入**：当前 S3 并不能直接提供全部 `SourceSnapshot` 和交接作用范围的生产字段。若 B 实验中使用人工核实、整理后才得到的 `verified` 或 `handoffIncludedIds`，须将相应实际准备与核查时间计入 B 的 `elapsedMs` 原始操作收据，并让 A/C 获得同等原始材料；不能从 G* 标注者的判断直接填入 B 可见输入而不记录成本。没有可审计的来源或交接范围证据时必须填 `unknown` / `null`，分层保守归为 `must_review`。此项属于人工审计门禁，程序验证 SHA 格式不等于验证现场成本。
- flat 与 tiered 在同一冻结 `Research.impacts` 预测集合上对比：flat 全部待核对，tiered 由无模型调用、无真值输入的保守纯函数输出 `must_review/before_use`。`reviewNeeded` 安全状态及所有详情/Handoff 的“上游已变更未复核”不消失。`deferred` 只来自真实用户操作（`triggerEventId`、目标 ID、冻结目标版本 `targetVersionId`、非空理由、独立收据），且目标必须在本事件预测影响集合内；不算预测命中，不自动确认/关闭；新 `triggerEventId` 必须重开。
- 输出每事件/每案例的 flat 条数、必须核对条数、下降比例，必须核对层对**实质 G*** 的召回（≥90% 为筛选参考）、关键漏报数（**0 为上线硬门槛**），以及实质目标落入 `before_use` / `deferred` 的数量。关键漏报非零时禁止分层，回退 flat，聚合仍可保留且不得藏掉安全标记。
- 三臂均须保留可定位到结论目标的操作 `reviewSegments=[{targetConclusionId,elapsedMs,learningMs,receiptId}]` 和 `reviewLogComplete:true`；每条时间不能超过臂总实际耗时。原有 `learningMs` 仍累计于臂总耗时，分段中未分配的学习时间**另报未知**，不补零、不作为可比的噪声占比。无实质复核时间仅来自 `non_substantive` G* 或不在 G* 的误报目标；分别报告不含学习成本与含已分配学习成本两种口径。以六案例内 B−A 的无实质复核时间占比差值中位数 ≤0 为筛选参考，同时给出各案例差值和案例聚类区间；任何案例缺乏可归因日志或学习时间时整体比较记为未知，不作有利判断。
- 三臂每事件另留 `handoffCorrectSubstantiveIds`，必须是由独立人工检查最终交接后确认正确的实质 G* 子集；“被提醒”不等于“已纠正”。由此计算每案例、三臂的**重要错误捕获并纠正率**，按案例聚类报告而非把 30 事件视作 30 个独立样本。
- 冻结执行顺序不变：先明确并审定上述字段/规则，冻结 G*、规则 SHA 和完整案例协议，然后才跑预注册的离线 flat/tiered 对照；**只有关键漏报 0 才进入 S3 提醒分组 UI 审核**。三臂 B 使用同一个通过离线门禁的 tiered 版本；若分层不合格，退回 flat 并在结果中记录版本变动，不混为同一 B。
- 继续使用原 `threadline-s2-pilot/1` 及原 A/B/C 定义，不添加第四臂或概率/效用评分。B 正确接续率不高于 A、或 B 对 A 的含学习成本中位耗时改善 <15%、或重要安全门槛不通过时，不扩张 S2–S5，保留 S1。六案例仅用于可行性筛选。

## 计算与作弊约束

- B 臂预期影响必须由项目**相同的** \`Research.impacts(frozenState,projectId,[rootConclusionId])\` 代码重新计算。观测文件中禁止包含人工填入的 \`B.predictedAffectedIds\`；不允许用标注 \`goldAffectedIds\` 替换预测。报告逐事件 TP/FP/FN 和未提醒的关键错误。
- A/C 的判断正确性、对真实判断的误改，以及三臂总耗时均依据**独立原始记录**填写，不以模型答复自评分替代。每次操作填写 `elapsedMs`（完整操作耗时，不含首次学习）与 `learningMs`（学习成本在该案例/臂的多个事件中只分配一次，其他事件写 0）；按研究案例汇总**计入学习成本/不计学习成本**两种总耗时与增益，正式筛选以计入学习成本为准。输出每例事件级和案例级结果，未完成的事件不允许静默剔除。
- 变化事件属于同一研究案例的相关观测；案例才是主要独立单位。固定随机种子的 2,000 次**案例聚类**重采样只报告描述性不确定性，不能作为确认性检验。
- 旧门槛：必要边完整 ≥90%，影响召回 ≥90%、精确 ≥80%，关键漏报 0，中位耗时改善 ≥15%，至少 4/6 案例不慢于 A；仅作为是否扩大独立案例投入的筛选条件，不能证明总体效果。
- 完整 A/B/C 独立研究所需的第二人、真实登录与必要预算属于人工门禁；**本开发 PR 绝不编造数据或填充通过指标**。
