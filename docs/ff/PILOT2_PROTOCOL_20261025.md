# Pilot/2 研究接续三臂可行性筛选（2026-10-25）

**状态：协议与评估器工程候选；真实研究执行 NOT_EXECUTED。** 与已存在的 \`threadline-s2-pilot/1\` 并存，不篡改原协议、门槛或历史记录。

## 研究问题

在同样研究资料、模型可用条件和预算下：S1+S2/S3/S4 的定向核查（B）相对已有 S1 流程（A）以及在新 ChatGPT 对话直接重做整个问题（C），能否减少错误接续、错误修订和人工操作时间？只做可行性筛选，不声称因果、普遍效益或统计验证。

## 预注册和原始真值

1. 在 **任何三臂运行前**，由人工形成 6 个不同脱敏研究案例，每例至少 5 个预设变化事件，共至少 30 次，包含关键前提错误、指标口径变化、来源丢失、仅措辞变化和无关分支。
2. 人工独立标注每个案例的必要边真值 \`goldNecessaryEdgePairs\`、每事件影响真值 \`goldAffectedIds\`、关键错误事件 \`critical\`；至少 2 个案例两人独立标注，再解决分歧。不得从工具运行的预测反向标注真值。
3. 三臂顺序交叉，控制可见资料、模型版本、预算；C 臂给模型相同原始材料与研究问题，让其自然直接重做。记录模型调用、工具调用、全部人工核查/恢复耗时，不允许只统计成功点击。已学习正确答案的操作者不得被悄悄重用为独立样本。
4. 每事件预先登记相同原始资料的 `sourceCorpusSha256`，A/B/C 各自收据必须证明引用同一份原始资料、相同模型版本；不同事件或臂的收据 ID 不允许重复。将完整协议 JSON（含每事件**事先冻结**的 B 图和版本状态）以 Git commit 单独登记，标记 \`status:FROZEN\`、冻结时间、commit SHA、预审人员。记录原始文件字节的 SHA-256；冻结后修改任何字节都要求新协议版本和重新预注册，不能拼接不同版本。
5. 与协议分开保存观测 JSON；只有在全部真实操作、原始脱敏收据和所有三臂记录齐全后标记 \`status:EXECUTED\` 并填 \`protocolSha256\`。模板刻意写入 NOT_EXECUTED，不可直接当数据使用。

## 计算与作弊约束

- B 臂预期影响必须由项目**相同的** \`Research.impacts(frozenState,projectId,[rootConclusionId])\` 代码重新计算。观测文件中禁止包含人工填入的 \`B.predictedAffectedIds\`；不允许用标注 \`goldAffectedIds\` 替换预测。报告逐事件 TP/FP/FN 和未提醒的关键错误。
- A/C 的判断正确性、对真实判断的误改，以及三臂总耗时均依据**独立原始记录**填写，不以模型答复自评分替代。输出每例事件级和案例级结果，未完成的事件不允许静默剔除。
- 变化事件属于同一研究案例的相关观测；案例才是主要独立单位。固定随机种子的 2,000 次**案例聚类**重采样只报告描述性不确定性，不能作为确认性检验。
- 旧门槛：必要边完整 ≥90%，影响召回 ≥90%、精确 ≥80%，关键漏报 0，中位耗时改善 ≥15%，至少 4/6 案例不慢于 A；仅作为是否扩大独立案例投入的筛选条件，不能证明总体效果。
- 完整 A/B/C 独立研究所需的第二人、真实登录与必要预算属于人工门禁；**本开发 PR 绝不编造数据或填充通过指标**。
