# 研线 ThreadLine v0.5.0

用于同时打开多条 ChatGPT 研究对话的 Chromium 浏览器扩展。目标是在切回任何研究窗口时，立即判断当前分支是否已经过时、课题是否收口，并能一键跳到同课题的其他分支。

## 安装与从 v0.4.1 升级

1. 下载并解压 `ThreadLine-v0.5.0.zip`，找到包含 `manifest.json` 的 `threadline-extension` 文件夹。
2. Edge 打开 `edge://extensions/`；Chrome 打开 `chrome://extensions/`，开启「开发人员模式」，点击「加载解压缩的扩展程序」，选中 `threadline-extension` 文件夹。
3. 如果已经安装旧版，建议**先备份原扩展目录，随后将新版文件覆盖到原来的同一路径**，在扩展管理页按「重新加载」，最后刷新已打开的 ChatGPT 页面。不要卸载旧版再装，否则旧扩展的本地数据可能被清除。
4. 点击扩展工具栏图标打开侧栏。默认显示「对话切换」。

浏览器按扩展 ID 隔离本地数据；更换安装路径可能导致 ID 改变。是否保留数据以扩展 ID 为准。

## 1. 对话切换（默认首页）

- 查看当前窗口所属课题、研究目标和已登记的有效结论。
- 「同课题对话」直接显示所有已关联分支、是否正在回答、研究状态以及是否有未核对的课题更新。点另一个分支直接切回已打开标签页；原标签未打开时使用保存的 ChatGPT 对话 URL 重新打开。
- 未关联的对话可以从下拉框选已有课题并点击「关联当前对话」，也可以一键创建新的临时课题。
- 「管理课题」可更新目标、有效结论、进度及整题收口状态；「全部课题与管理」默认折叠，避免占据切换时的第一屏。

### 「待同步版本」如何产生

只有在用户明确保存**内容发生变化的研究目标、有效结论或收口状态**时，整个课题的 `knowledgeVersion` 才加一。只是重命名、再次打开对话、收到新的 AI 回复、重新关联旧分支，不会被误认为出现新结论。

每条分支保存其最后人工核对过的版本 `seenVersion`。一条分支未核对新的课题版本时，侧栏和该 ChatGPT 页面的角落会显示提醒。它**不会自动认定旧分支的研究错误**，也不会因仅仅有待同步版本而拦截发送。

阅读结论后点击「已核对最新状态」才会清除提醒。已收口课题或手动标记已完成的分支仍保留原有发送拦截确认。

### 发布研究新状态

在「管理课题」中更新有效结论并保存。当前被选中的同课题分支视为这次发布的来源，自动核对到最新版本；其他分支保留待核对提示。若面板当前没有对应源分支，则所有相关分支仍需要人工核对。

## 2. 研究整理（第二页）

继续保留 v0.4.1 的「采集并整理」：选择一个已保存且已打开的 ChatGPT 对话，读取所能获取的历史文本，报告覆盖情况；可以生成规则提要、调用可选模型产生结构化分析和交互思维导图。

分析方式维持：ChatGPT 网页自动分析（实验性）、ChatGPT 手动分析导入、可选 Ollama、独立 OpenAI API。网页自动分析基于非公开 UI，不属于官方模型 API；本版本未更改其既有限制。

**新增「将 AI 结论提交为课题新状态」：** 仅在报告属于进行中的已关联课题且已完成 AI 分析时出现。点击后将模型提取的候选结论放进可编辑确认框，只有用户审核并再次确认后才更新共享课题的有效结论。模型不会自主收口。即使历史文本采集不完整，也必须由用户承担审阅和校正，不能把 AI 提议作为已验证事实。

保留「创建 ChatGPT 网页项目并移入」和「归档此对话」，操作对象是被采集的源对话，不会自动改变本地课题状态；这些功能需真实登录网页验收，遇到结果不确定会停止盲目重试。

## 3. 技术和数据

- 无云端中转服务器。临时课题保存在 `chrome.storage.local` 中（沿用旧键 `threadline_state_v1`）；采集正文缓存在 IndexedDB，默认 3 天清理。
- 状态结构沿用 schema 1，读取时自动为旧记录补 `knowledgeVersion`、`seenVersion`，旧项目不会因为升级产生虚假的「待核对」提醒。旧的课题 ID、对话关联、阶段与采集记录保留。
- 后台使用串行写入，减少多标签页同时修改时的数据覆盖。
- 浏览器扩展只观察对话标题、链接及是否正在回答，不常态上传对话正文。只有用户启动采集及 AI 分析时，才处理对应来源文本。
- 所有网页自动化依赖外部页面及使用授权；请先在非重要测试对话中验证实际效果。

## 4. 检验

解压后在 `threadline-extension` 目录运行：

```bash
node --test test/*.test.js
```

需要 Python Playwright 和 Chromium 的离线模拟测试：

```bash
python test/switch-ui-smoke.py
python test/overlay-ui-smoke.py
python test/organize-ui-smoke.py
```

特别说明：切换界面的模拟测试使用 `about:blank`，无法在该来源调用 IndexedDB，因此只检验首页、标签切换与渲染，并没有把模拟环境的 IndexedDB 错误算作扩展本身的采集失败。真实网页登录/分页采集、AI 提供商请求和网页创建项目/归档均未在这次离线测试中获得端到端证明。
